🔍 Анализ проблемы с миграционными данными

❌ Симптом проблемы

После изменений в коде значения, возвращаемые методом TotalMigration.saldo(), изменились для всех лет и для всех губерний с Самарской по Ярославскую в алфавитном порядке, но не для других губерний.

При этом файлы данных Excel со значениями миграции не менялись, и изменения были предназначены для файлов УГВИ, а не миграции.

🔎 Найденная причина

1. Изменения в TerritoryNames.canonic()

Файл: rtss-pre1917/src/main/java/rtss/pre1917/data/TerritoryNames.java

В метод TerritoryNames.canonic() были добавлены три строки:

ter = ter.replace("Итого во ", ""); ter = ter.replace("Итого ", ""); // ← ПРОБЛЕМНАЯ СТРОКА ter = ter.replace("Всего ", ""); // ← ПРОБЛЕМНАЯ СТРОКА

Эти строки находятся на строках 51, 55, 57 файла TerritoryNames.java.

2. Как это влияет на чтение миграции

При загрузке файлов внутренней миграции используется метод:

LoadData.java:1839 → canonicAreaName()

private String canonicAreaName(String aname) throws Exception { aname = Util.despace(aname).trim(); if (!isAggregateAreaName(aname)) { aname = TerritoryNames.canonic(aname); // ← ВЫЗОВ ПРОБЛЕМНОГО МЕТОДА TerritoryNames.checkValidTerritoryName(aname); } return aname; }

3. Порядок выполнения (где происходит ошибка)

Шаг 1: В файле миграции встречается название вроде "Итого Самаркандская" или "Всего Семипалатинская"
Шаг 2: Вызывается canonicAreaName("Итого Самаркандская")
Шаг 3: Проверяется isAggregateAreaName("Итого Самаркандская") → возвращает false
(потому что в списке агрегатов нет строки "Итого Самаркандская", есть только "Итого по Степному краю..." и подобные)
Шаг 4: Вызывается TerritoryNames.canonic("Итого Самаркандская")
Шаг 5: Внутри canonic() выполняется ter.replace("Итого ", "")
Результат: "Итого Самаркандская" → "Самаркандская"
Шаг 6: Затем алиас превращает "Самаркандская" в "Самаркандская обл."
(потому что в TerritoryNames есть: aliases("Самаркандская обл.", "Самарканская", "Самаркандская", "Самаркандская область"))
Шаг 7: ❌ ОШИБКА: Данные для агрегата "Итого Самаркандская" записываются как данные для территории "Самаркандская обл."

🎯 Затронутые файлы данных

Проблема может проявиться при чтении следующих файлов:

  • inner-migration/inner-migration-yearly.xlsx
  • inner-migration/inner-migration-coarse.xlsx
  • inner-migration/inner-migration-coarse-loadable.xlsx
  • immigration.xlsx (если использует те же методы)
  • emigration.xlsx (если использует те же методы)

Примечание: Методы loadImmigration() и loadEmigration() не вызывают canonicAreaName(), поэтому они могут быть не затронуты. Основная проблема в loadInnerMigration().

✅ Решение проблемы

Вариант 1: Удалить проблемные строки (рекомендуется)

Удалить или закомментировать строки 55 и 57 в TerritoryNames.java:

// ter = ter.replace("Итого ", ""); // УДАЛИТЬ // ter = ter.replace("Всего ", ""); // УДАЛИТЬ

Оставить только более специфичные замены:

ter = ter.replace("Итого в ", ""); ter = ter.replace("Итого во ", ""); ter = ter.replace("Итого ва ", ""); ter = ter.replace("Итого на ", ""); ter = ter.replace("итого в ", ""); ter = ter.replace("Всего в ", "");

Вариант 2: Добавить недостающие агрегаты

Если в файлах миграции действительно есть строки "Итого Самаркандская" и т.п., добавить их в метод isAggregateAreaName():

case "Итого Самаркандская": case "Итого Семипалатинская": case "Итого Терская": case "Итого Тургайская": case "Итого Уральская": case "Итого Ферганская": case "Итого Якутская": case "Всего Самаркандская": case "Всего Семипалатинская": // ... и т.д. return true;

Вариант 3: Изменить порядок обработки

Применять замены "Итого " и "Всего " только для файлов УГВИ (DataSetType.UGVI), а не для файлов миграции.

🔍 Как проверить

  1. Откройте файлы миграции в Excel и найдите строки, содержащие "Итого" или "Всего" в сочетании с названиями областей
  2. Проверьте, есть ли в колонке "губ" значения вроде:
    • "Итого Самаркандская"
    • "Всего Семипалатинская"
    • И т.п.
  3. Если такие строки есть, то эти данные были неправильно присвоены конкретным территориям вместо агрегатов

📝 Дополнительные наблюдения

  • Алиасы типа "Самаркандская" → "Самаркандская обл." уже существовали в версии final_1896, так что это не новая проблема сама по себе
  • Проблема возникла именно из-за добавления слишком общих замен "Итого " и "Всего " без учета контекста
  • Метод isAggregateAreaName() работает правильно, но список агрегатов в нём неполный
  • Порядок обработки важен: сначала проверяется агрегат, потом применяется canonic(), но внутри canonic() уже происходят замены, которые могут превратить неучтённый агрегат в обычное название
